# Pinball Loop Visual Feedback AI Usage

- 사용한 AI 도구/모델: Codex, GPT-5 기반 코딩 에이전트
- 사용자 요청: 사운드는 미루고 핀볼 장전, 당김, 발사, 충돌, 골, 실패 루프의 나머지 피드백을 구현한다. 별도 설계 승인 없이 구현하고 정적 확인만 수행한다.
- AI 제안 내용: 기존 아케인 마스크, 공 링/충돌 스프라이트, 골 아크, Bloom 경로를 재사용해 행동 단계별 시각 강약을 연결한다.
- AI 실제 수정 영역: 플런저 장전 및 최소 당김 펄스, 공 장전 및 발사 버스트, 벽/핀/범퍼 충돌 강도 구분, 골 룬 펀치, 아웃 존 실패 이펙트, 다음 공 장전 피드백 연결.
- 사용자 직접 결정/수정 필요 영역: Unity Play Mode에서 연출 크기, 색, 지속시간의 체감 조정. 신규 아트 리소스는 현재 구현에 필요하지 않다.
- 중요한 프롬프트/지시: 사운드 제외, 설계 승인 생략, 정적 확인만 수행, 기존 물리와 게임 규칙 보존.
- 테스트/검증 결과: Unity 실행, EditMode 테스트, Play Mode 테스트는 사용자 요청에 따라 수행하지 않았다. `git diff --check`, 변경 diff와 참조 검색을 통한 정적 검사를 수행했다.
- 후속 조정: 첫 적용 후 타격감이 약하다는 사용자 피드백을 받았다. 코드 추적 결과 공의 충돌·발사 효과가 공의 자식이라 월드 충돌 지점에 머물지 않고 공을 따라가는 좌표계 문제가 확인되어, 해당 효과를 독립 월드 오브젝트로 변경하고 수명 정리를 추가했다.
- 두 번째 후속 조정: 사용자가 스프링 밝기, 손잡이 발광, 플런저 스냅, 화면 흔들림, 골 룬 점등, 골 진입 연출, 범퍼 골드 파티클의 부재를 구체적으로 보고했다. 씬과 호출 경로를 확인한 결과 스프링에는 발광 렌더러가 없고, 플런저 복귀는 즉시 대입이며, 카메라 피드백 경로가 없고, 골 Rune에는 발광 컨트롤러가 없어 기존 펄스 호출이 무시되며, 골드 지급은 수치 변경만 수행하는 것이 원인이었다. 기존 아케인 셰이더와 스프라이트를 재사용해 해당 출력 경로를 추가했다.
- 두 번째 후속 검증: 사용자 요청에 따라 Unity 실행은 하지 않았다. `git diff --check`, 변경 C# 파일 중괄호 균형, SerializeField 네이밍, 호출/정의 연결을 정적으로 확인했다. 작업 전부터 존재한 `pinball_board_arcane_mask.png`와 `ItemData.json` 변경은 수정하지 않았다.
- 골드 팝업 조정: 사용자가 범퍼 골드 보상을 일반 파티클 대신 충돌 지점에서 `(골드 아이콘) +지급량`이 상승하며 사라지는 형태로 요청했다. 기존 HUD 골드 아이콘을 VFX 카탈로그에 연결하고, 연속 충돌을 지원하는 4개 월드 팝업 풀로 기존 금색 스파크를 교체했다. 표시 위치는 공 중심이 아니라 실제 `Collision2D` 접촉점이며 숫자는 기본 보상과 황금 범퍼 추가 보상의 실제 합계를 사용한다.
- 골드 숫자 표시 수정: 실제 확인에서 아이콘만 보이고 숫자가 보이지 않았다. 팝업 생성과 좌표는 정상이며 런타임 `TextMeshPro`만 기본 폰트, 텍스트 영역, 오버플로, 렌더 정렬, 활성화 후 메시 갱신을 명시하지 않은 상태였다. 해당 설정을 명시적으로 적용했으며 `Assembly-CSharp.csproj` 정적 빌드 결과 오류 0개, 기존 의존성 경고 7개였다.
