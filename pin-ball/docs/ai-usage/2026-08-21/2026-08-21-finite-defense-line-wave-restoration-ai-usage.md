# 유한 웨이브·방어선 전투 복구 AI 활용 기록

## 사용 도구/모델

- Codex (GPT-5 계열)
- 로컬 Git 비교, 정적 검색, .NET C# 컴파일

## 사용자 요청

- 작업 브랜치: `temp`
- 준비 단계와 수동 웨이브 시작, 고정 10웨이브, 웨이브 재시도, 최종 승리 복구
- 승패 조건을 유닛 전멸이 아닌 상대 방어선 HP 0으로 변경
- 아군/적군 방어선 HP를 각각 별도 관리하고 시도마다 초기화
- `PlayerHp`를 3회의 도전 기회로 사용
- 전투 중 아군 구매와 전술 증원 유지
- 방어선 HP 강화는 아군 방어선 최대/현재 HP +10
- 웨이브 클리어·재시도·최종 승리 골드 보상 삭제
- Dev 대비 다른 변경을 나중에 제거하기 쉽도록 문서화

## AI 제안 내용

- 웨이브 진행 상태와 한 판의 지속 상태를 분리
- 양 진영 방어선을 공통 컨트롤러에서 관리
- 유닛이 상대 방어선에 도달하면 방어선에 피해를 주도록 기존 전투 흐름 연결
- 씬 배치와 Inspector 참조를 유지하며 최소 범위로 UI/결과창 복구
- 무한 스테이지 전용 컨트롤러와 보상 필드를 제거

## AI 실제 수정 영역

- 전투 상태/웨이브 결과: `Assets/02.Scripts/Battle`
- 방어선 피격 및 유닛 이동·공격 연결: `Assets/02.Scripts/Unit`
- 웨이브 시작, HUD, 결과 표시: `Assets/02.Scripts/UI`
- 강화 효과 연결: `Assets/02.Scripts/Upgrade`
- 씬 참조와 결과 아트: `Assets/01.Scenes/Game.unity`
- 관련 EditMode 테스트 추가·수정
- 무한 스테이지 전용 코드/테스트 삭제
- 향후 제거용 기능 목록: `docs/plans/2026-08-21/2026-08-21-temp-branch-removal-inventory.md`

## 사용자 직접 결정 영역

- 총 웨이브 10
- 도전 기회 3
- 양측 방어선 초기 HP 20
- 방어선 HP 강화량 +10
- 유닛 전멸은 즉시 승패 조건이 아님
- 전술 증원 유지
- Unity 라이선스 복구 전에는 실행 테스트 없이 코드·정적 검사로 진행

## 중요 지시

- 다른 temp 변경은 즉시 제거하지 않고 목록화
- 수동 핀볼 발사, 골 포켓 아군 생성, 카메라 슬라이드는 복구 대상에서 제외
- 기존 구조와 사용자 수정 패턴 유지

## 테스트/검증 결과

- `dotnet build Assembly-CSharp-Editor.csproj --no-restore`: 성공, 오류 0, 경고 6(기존 Unity/SDK 참조 버전 충돌)
- 정적 검색: 런타임 코드에서 무한 스테이지 컨트롤러와 골드 보상 필드 제거 확인
- 전술 증원 심볼과 테스트 유지 확인
- `git diff --check`로 공백 오류 검사
- Unity EditMode 실행은 Unity LicensingClient 재연결 실패로 테스트 시작 전에 차단됨. 테스트 통과를 주장하지 않음.

- HUD와 승리/패배 아트의 실제 해상도별 배치 확인 필요
