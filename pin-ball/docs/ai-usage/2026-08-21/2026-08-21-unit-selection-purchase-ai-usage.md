# 전사·궁수·마법사 선택 구매 AI 활용 기록

## 사용한 AI 도구/모델

- Codex
- GPT-5 계열 모델

## 사용자 요청

- 기존 단일 `UnitPurchase` 구매를 전사, 궁수, 마법사 선택 구매로 교체
- 유닛별 비용과 성공 횟수를 독립 관리
- Spawn 성공 뒤에만 골드 차감과 성공 횟수 기록
- 구매 흐름과 직접 연결된 책임 및 이벤트 정리
- `App/AppService`, `UIManager/UIBase` 구조 유지
- 전술 증원권과 신규 구매 UI 제외

## AI 제안 내용

- 일반 전투 강화와 유닛 구매를 분리하는 `UnitPurchaseController` 도입
- 전사 30G, 궁수 35G, 마법사 40G와 공통 비용 배율 1.4 제안
- 구매 성공 결과만 `OnAllyPurchased`로 알리고 내부 단계는 동기 반환값으로 연결
- 무료 구매가 추후 같은 성공 횟수 기록을 사용할 수 있도록 별도 기록 API 제공

## AI 실제 수정 영역

- 선택 구매 설정, 비용 계산, 성공 횟수와 구매 트랜잭션 구현
- `BattleManager`에 선택 구매 조회 및 실행 API 연결
- `BattleUpgradeController`에서 기존 `UnitPurchase` 책임 제거
- 구매 계측 이벤트를 일반 전투 강화 이벤트와 분리
- 기존 단일 유닛 구매 UI 오브젝트 비활성화
- 구매 성공과 실패 조건을 다루는 EditMode 테스트 추가
- 기존 구매 행을 전사, 궁수, 마법사 가로 3카드 UI로 교체
- 각 카드의 버튼, 역할, 구매 횟수와 현재 비용 표시 연결
- 구매 카드 씬 참조와 표시 문자열 EditMode 테스트 추가

## 사용자 직접 결정/수정 필요 영역

- 플레이 관찰에 따른 세 유닛 기본 비용과 증가 배율 조정

## 중요한 프롬프트/지시

- 구매 흐름과 직접 연결된 이벤트만 정리
- 기존 사용자 작업 트리 보존
- 전체 테스트, 전체 빌드, WebGL 빌드와 장시간 플레이 검사 금지
- 자동 스테이징 및 커밋 금지
- `[SerializeField]` 필드에 underscore 사용 금지

## 테스트/검증 결과

- `git diff --check`로 공백 오류를 검사했다.
- Unity가 생성한 `Assembly-CSharp.rsp` 참조를 사용한 Roslyn 컴파일로 런타임
  스크립트와 신규 EditMode 테스트 코드의 컴파일 오류가 없음을 확인했다.
- 선택 구매 EditMode 테스트 실행을 시도했으나 로컬 Unity Licensing Client가
  패키지 권한을 확인하지 못해 Test Runner 진입 전에 중단되었다.
- Roslyn 컴파일에는 기존 `PinballManager`의 미사용 이벤트·필드 경고 4건만 있었다.
- 전체 테스트, 전체 빌드, WebGL 빌드와 장시간 플레이 검사는 실행하지 않았다.
