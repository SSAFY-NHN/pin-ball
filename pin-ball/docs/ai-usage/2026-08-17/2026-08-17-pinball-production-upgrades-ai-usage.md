# 핀볼 생산 업그레이드 AI 활용 기록

## 사용한 AI 도구/모델

- OpenAI Codex
- Unity 6.0.0.79f1 배치 모드
- Unity Test Framework / NUnit

## 사용자 요청

자동 공 순환과 BigBumper 골드 생산 위에 범퍼 수익, 영구 공 추가, 공급 속도 업그레이드를 구현하고 최소 생산 경제 루프를 완성한다.

## AI 제안 내용

- `PinballManager`가 생산 흐름과 구매를 조율한다.
- 순수 C# Controller가 비용, 레벨, 효과와 최대치를 계산한다.
- 영구 공 슬롯과 Split Capsule 복제 공을 별도 풀로 관리한다.
- 공급 속도는 구매 후 새로 예약되는 공부터 적용한다.
- 씬 배치 Button/TMP UI와 사전 배치 공을 사용한다.

## AI 실제 수정 영역

- 생산 업그레이드 계산 및 구매 검증
- 영구 공/복제 공 풀 분리
- BigBumper 업그레이드 수익 연결
- 공별 재생성 예약 및 새 런 초기화
- 생산 업그레이드 UI Controller와 Game 씬 UI
- Game 씬 영구 공 10개, 복제 공 3개, 자동 생성 지점
- 수동 플런저 입력, 발사 비용 표시, 기존 튜토리얼 비활성화
- BoardGlow 부모/자식 직렬화 정상화
- 시작 골드 0 설정

## 사용자 직접 결정/확인 필요 영역

- 초기 비용과 효과 수치의 실제 플레이 밸런스
- 생산 UI의 최종 배치와 아트
- Unity Editor에서 장시간 다중 공 물리 안정성 확인

## 중요한 지시

- 기존 전투, 범퍼 물리, VFX/SFX를 수정하지 않는다.
- 공은 Instantiate/Destroy 대신 씬 사전 배치와 SetActive 풀링을 사용한다.
- Split Capsule 복제 공은 영구 슬롯으로 전환하지 않는다.
- 불필요한 전체 검사와 검사를 위한 검사를 실행하지 않는다.

## 테스트/검증 결과

- 관련 EditMode 테스트 13개 통과
  - 비용 공식과 선형 범퍼 수익
  - 골드 부족 구매 실패
  - 영구 공 최대 10개
  - 최소 재생성 시간 0.75초
  - 새 런 초기화
  - 영구 공/복제 공 풀 분리
  - 공별 재생성 예약
- Unity 스크립트 컴파일 성공. 기존 수동 발사 API 잔존으로 경고 4건이 있었으며 컴파일 오류는 없었다.
- Game 씬 자동 Play 검증은 앱 시작 서비스가 없는 단독 씬 실행 문제와 배치 실행 정지로 완료하지 못했다. 임시 검증 스크립트는 제거했다.
- Game 씬은 불필요한 재직렬화 이동을 제거해 기존 블록 순서를 복원하고, 기능에 필요한 새 오브젝트와 참조만 추가했다.
- `ProjectSettings` 변경은 모두 복원했다.
- 기존 공의 물리 수치 `launchSpeed 12`, `maximumSpeed 12`, `linearDamping 0.35`, `gravityScale 0.35`를 새 공 Prefab에도 동일하게 적용했다.
