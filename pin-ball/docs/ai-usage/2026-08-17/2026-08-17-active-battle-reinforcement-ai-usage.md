# 전투 중 아군 즉시 재투입 AI 활용 기록

## 사용한 AI 도구/모델

- Codex
- GPT-5 계열 모델

## 사용자 요청

- 마일스톤 1이 반영된 작업 트리에서 남은 마일스톤 2만 구현
- 아군 전멸 후 적이 방어선으로 이동하는 동안 구매한 아군을 현재 단계에 즉시 투입
- 생존 적이 새 아군을 다시 탐색해 전투 재개
- 회수된 적은 복구하지 않고, 구매 실패 시 골드 보존
- 최대 보유 아군 5명과 기존 Spawn, 풀링, roster, 공용 공격력 배율 재사용

## AI 제안 내용

- 기존 구매와 타기팅 경로를 유지하고 마일스톤 1 이후 회귀만 최소 보강
- 전사 아군이 보유 roster에 남아 최대 인원을 점유하는 문제를 기존 단일 제거 경로에서 수정
- 빈 아군 roster에 새 아군이 등록된 뒤 타깃 탐색기가 즉시 찾는 동작을 회귀 테스트로 고정

## AI 실제 수정 영역

- `UnitRoster.NotifyUnitDied`가 전사 유닛을 active 목록뿐 아니라 owned 목록에서도 제거하도록 기존 `RemoveUnit` 경로 재사용
- 전멸 후 구매한 증원 아군이 owned와 active 목록에 즉시 등록되는 테스트 추가
- 빈 roster를 보던 적 타깃 탐색기가 새 증원 아군을 찾는 테스트 추가
- `BattleManager`, `UnitManager`, `EnemyUnit`, 씬, 프리팹은 기존 흐름이 요구사항을 충족해 수정하지 않음

## 사용자 직접 결정/수정 필요 영역

- 실제 Game 씬에서 방어선 이동 중 구매 버튼 입력, Spawn 위치, 전투 재개 연출을 직접 플레이로 확인해야 함
- 밸런스 수치와 최대 보유 아군 5명 규칙은 변경하지 않음

## 중요한 프롬프트/지시

- 승인 전 수정 금지, 승인 후 마일스톤 2만 구현
- 전체 테스트, 전체 빌드, WebGL 빌드 금지
- 핵심 경로만 최소 확인하고 반복 검사 금지
- 관련 없는 변경 보존
- 자동 스테이징과 커밋 금지

## 테스트/검증 결과

  - 전멸 후 증원 등록 시 owned 목록에 전사 아군과 증원이 함께 남음
- GREEN: 다음 EditMode fixture 4개, 총 13개 테스트 통과
  - `BattleEconomyTests`

- 전체 테스트, 전체 빌드, WebGL 빌드, PlayMode 직접 플레이는 수행하지 않음
