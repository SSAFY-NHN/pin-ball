# 보스 단계·프로토타입 계측 마일스톤 AI 활용 기록

## 사용한 AI 도구/모델

- Codex 기반 코드 분석 및 구현 도구
- 로컬 파일 검색, 패치 적용, Git diff 정적 확인

## 사용자 요청

10단계마다 기존 `goblin_king`을 단독 보스로 등장시키고, 현재 핀볼 생산·잭팟·업그레이드·지속 전투 밸런스를 화면에서 관찰할 수 있는 최소 런타임 계측을 추가한다. 테스트는 작성하거나 실행하지 않고 코드와 씬을 정적으로 확인한다.

## AI 제안 내용

- `BattleStageController`가 Inspector 보스 간격에 따른 단계 판정을 담당
- 일반 단계와 보스 단계를 `BattleManager.StartCurrentStage`에서 한 번만 분기
- 기존 단계 성장 스탯 생성 후 보스 체력·공격력 배율만 적용
- `UnitManager.BeginStage`가 실제 Spawn 수를 반환하고 0명이면 단계 시작 중단
- 별도 `PrototypeMetricsController`가 게임 이벤트를 구독해 제한된 카운터와 최근 단계 결과만 집계
- 별도 표시 Controller가 씬 배치 TMP를 0.75초 간격으로 갱신

## AI 실제 수정 영역

- 보스 단계 판정, Spawn 분기, 배율, Spawn 실패 중단과 보스 사망 이벤트
- 단계 시작·결과와 전투 업그레이드 구매 payload 이벤트
- 영구 공 활성화·회수, 범퍼 보상과 생산 업그레이드 구매 payload 이벤트
- 영구 공·복제 공을 분리한 런타임 계측 수집
- StatusPanel 보스 표기와 짧은 단계 강조
- Game 씬 `PrototypeMetricsPanel`과 TMP Inspector 참조

## 사용자 직접 결정/수정 필요 영역

- 보스 체력 배율 `1.25`, 공격력 배율 `1.0`의 실제 플레이 밸런스
- 계측 패널 위치와 가독성
- 첫 보스 도달 8~12분, 잭팟 3~7분과 구매 간격 목표 충족 여부
- 반복 실패 후 1~3회 강화 안에 보스를 돌파하는지 직접 관찰

## 중요한 프롬프트/지시

- 기존 `goblin_king` 데이터, 스킬, 외형과 적 풀링을 재사용한다.
- 일반 단계 성장 공식, 이동·공격 속도와 기존 경제 규칙을 변경하지 않는다.
- 보스 실패 시 성장 손실 없이 같은 단계를 유지한다.
- 계측은 관찰만 하며 저장·외부 전송·자동 밸런싱을 추가하지 않는다.
- OnGUI와 런타임 UI 생성을 사용하지 않는다.
- 테스트 파일 작성·수정·삭제와 테스트 실행을 금지한다.

## 테스트/검증 결과

- 테스트는 사용자 지시에 따라 작성·수정·실행하지 않았다.
- Unity 플레이, 배치 컴파일과 빌드는 실행하지 않았다.
- `git diff --check`로 공백 오류가 없음을 확인했다. 출력된 내용은 기존 줄 끝 형식 관련 경고뿐이다.
- 보스 판정, Spawn 분기·반환, 단계 유지·진행, 풀 회수 경로와 이벤트 구독·해제를 코드로 정적으로 확인했다.
- Game 씬에서 보스 Inspector 값, Metrics 두 컴포넌트, TMP와 Canvas 부모 참조를 정적으로 확인했다.
