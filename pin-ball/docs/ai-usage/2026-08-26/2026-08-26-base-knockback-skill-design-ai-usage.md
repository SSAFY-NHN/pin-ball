# 기지 전선 밀어내기 스킬 설계 AI 활용 기록

## 사용 도구/모델

- Codex (GPT-5 계열)
- 로컬 Git과 저장소 코드·문서 읽기
- Superpowers brainstorming 절차

## 사용자 요청

- 준비 단계보다 다른 마일스톤을 먼저 검토
- 첫 기지 액티브 스킬로 전투 중 적 전체 넉백 선택
- 시작 즉시 사용할 수 없고 전투 게임 시간 30초 후 해금
- 웨이브당 1회만 사용
- 넉백 거리는 고정 3 Unity 유닛
- 전장 경계 밖 이동 허용
- 방어선 공격 중인 적도 밀어내고 다시 이동하도록 처리

## AI 제안 내용

- 첫 기지 스킬을 피해 없는 전선 복구 수단으로 제한
- 순수 C# 상태 컨트롤러, `BattleManager` 중재, `UnitManager` 효과 적용과 씬 배치 UI로 책임 분리
- 기존 `UnitBase` 넉백과 면역 규칙 재사용
- 실제로 한 명 이상 넉백된 경우에만 사용권 소비
- 게임 시간 기반 30초 해금으로 기존 공세 시간표와 배속 규칙 유지
- 신규 이미지, 사운드와 전장 VFX는 후속 범위로 분리

## AI 실제 수정 영역

- 기술 설계 문서 작성
- 본 AI 활용 기록 작성
- 런타임 코드, 테스트, 씬, 애셋과 ProjectSettings는 수정하지 않음

## 사용자 직접 결정 영역

- 기지 액티브 스킬을 다음 마일스톤으로 선택
- 전투 30초 후 해금, 웨이브당 1회
- 넉백 면역 존중
- 방어선 공격 상태 해제
- 고정 3 유닛 넉백
- 전장 경계 밖 이동 허용과 정상 복귀 보장
- 추천 책임 분리 구조와 UI 상태 표시 승인

## 중요 지시

- 설계 승인 후 문서 작성
- 구현 계획 승인 전 코드 수정 금지
- 씬 배치 UI와 Inspector 참조 우선
- 외부 패키지, 런타임 UI 자동 생성과 요청 없는 리팩터링 금지
- 사용자 소유 애니메이션·VFX·ProjectSettings 변경 보존

## 테스트/검증 결과

- 기존 넉백, 넉백 면역, 방어선 도달, 적 로스터, 전투 시간과 UI 상태 구조를 읽기로 확인
- 설계의 상태 전이, 성공 조건, 실패 불변 조건, 검증 범위와 비범위를 자체 검토
- 코드 변경이 없어 Unity 테스트와 컴파일은 실행하지 않음

## 제한점/직접 확인 필요

- 구현 전 Game 씬의 실제 버튼 배치 위치와 재사용 가능한 강조 표현을 확인해야 함
- 구현 후 경계 밖으로 밀린 적이 콜라이더에 갇히지 않고 정상 복귀하는지 Unity에서 직접 확인해야 함
- 전체 EditMode의 기존 비관련 실패 5개와 새 회귀를 구분해야 함
