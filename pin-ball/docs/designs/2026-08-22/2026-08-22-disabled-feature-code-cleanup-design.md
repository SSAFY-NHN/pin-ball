# 비활성 기능 코드 정리 설계

## 목표

`temp` 브랜치에서 삭제되었거나 의도적으로 비활성화된 기능의 잔여 코드만 제거한다. 현재 사용하는 전투·핀볼 흐름은 보존하며, 함수 → 변수 → 클래스 → 스크립트 순서로 정리한다.

## 범위

### 제거 후보

- 드래그 합성·진화 흐름과 관련 UI, 이벤트, 데이터, 테스트
- 비활성 레거시 튜토리얼과 삭제 기능 전용 연결
- 수동 핀볼 발사와 골 포켓 유닛 생성의 잔여 코드
- 실제 참조가 없는 기존 패널 슬라이드 코드
- 삭제된 무한 스테이지와 웨이브·재시도 골드 보상의 잔여 참조
- 방어선 트리거에 필요하지 않은 `Use Full Kinematic Contacts` 설정

### 보존 대상

- 고정 10웨이브, 수동 웨이브 시작, 재시도, 최종 승리
- 양측 방어선 HP와 방어선 파괴 기반 승패
- 전술 증원과 선택형 아군 구매
- 아군 드래그 위치 이동
- 자동 핀볼 순환, 생산 업그레이드, 콤보, 황금 공, 잭팟
- 화면 흔들림에 사용 중인 `BattleCameraController`

## 판정 기준

코드 검색 결과만으로 삭제하지 않는다. 다음 조건을 모두 확인한다.

1. C# 호출·구독·상속·생성 참조가 없다.
2. 씬, 프리팹, ScriptableObject의 GUID 또는 직렬화 필드 참조가 없다.
3. Unity 메시지, 버튼 콜백, 애니메이션 이벤트, Editor 코드에서 호출되지 않는다.
4. 보존 대상 기능의 데이터 흐름에 참여하지 않는다.
5. 테스트가 삭제 기능만 검증하며 보존 기능의 회귀 방지 역할을 하지 않는다.

판정이 불확실한 항목은 삭제하지 않고 후속 후보 목록에 남긴다.

## 정리 순서

### 1. 안 쓰이는 함수 삭제

- 비활성 기능의 공개 진입점, 내부 처리 함수, 이벤트 핸들러를 제거한다.
- 호출부를 먼저 제거하고 참조 검색과 컴파일로 확인한다.
- Unity 메시지는 씬 컴포넌트 생존 여부까지 확인한다.

### 2. 안 쓰이는 변수 삭제

- 함수 제거 후 남은 필드, 프로퍼티, 이벤트, 상수, 직렬화 필드를 제거한다.
- 직렬화 필드는 씬·프리팹 YAML 데이터도 함께 정리한다.
- 방어선의 `Use Full Kinematic Contacts`를 끄되 Kinematic `Rigidbody2D`와 Trigger는 유지한다.

### 3. 안 쓰이는 클래스 삭제

- 앞 단계 후 참조가 0개인 타입만 제거한다.
- 한 파일에 여러 타입이 있으면 미사용 타입만 삭제한다.
- 보존 기능과 책임을 공유하는 클래스는 삭제하지 않는다.

### 4. 안 쓰이는 스크립트 삭제

- 클래스가 모두 제거된 `.cs`와 대응 `.meta`를 삭제한다.
- 전용 테스트 스크립트와 씬 오브젝트도 같은 단계에서 제거한다.
- 삭제한 GUID가 Assets 아래에 남지 않았는지 검사한다.

## 변경 단위

각 단계는 독립 커밋으로 만든다. 단계마다 이전 단계의 결과가 컴파일 가능한 상태여야 한다. 기능 변경이나 새 추상화는 포함하지 않는다.

## 검증

- 제거 심볼 전체 `rg` 재검색
- 삭제 스크립트 GUID의 씬·프리팹·에셋 참조 검사
- Unity C# 프로젝트 컴파일
- 관련 EditMode 테스트
- 고정 웨이브, 방어선 공격, 아군 구매, 전술 증원 관련 테스트 유지 및 실행
- `02. Game.unity`에서 Missing Script 여부 검사

Unity 라이선스 문제로 Editor 검증이 불가능하면 C# 컴파일과 정적 참조 검사 결과만 보고하고, 미실행 검증을 명시한다.

## 안전 제한

- 사용자 변경 파일인 `Assets/05. Animations/Rabbit/Rabbit1_Mage_Attack.anim`, `Assets/Resources/ArcaneVFX/ArcaneVfxCatalog.asset`는 수정·스테이징하지 않는다.
- 관련 없는 파일 이동, 이름 변경, 포맷팅, 패키지 변경은 하지 않는다.
- 현재 사용 여부를 증명하지 못한 코드는 삭제하지 않는다.

## 완료 조건

- 요청한 네 단계가 순서대로 완료되고 각 단계가 독립 커밋으로 남는다.
- 제거 대상으로 확정한 심볼과 GUID 참조가 0개다.
- 보존 대상 코드와 씬 참조가 유지된다.
- 가능한 검증이 통과하고 실행하지 못한 검증이 명확히 기록된다.
- AI 활용 기록과 제거 목록 문서가 실제 변경 결과에 맞게 갱신된다.
