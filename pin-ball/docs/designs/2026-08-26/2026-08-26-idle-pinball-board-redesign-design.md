# 방치형 핀볼 보드 재구성 설계

- 작성일: 2026-08-26
- 상태: 사용자 승인
- 대상 씬: `Assets/01. Scenes/02. Game.unity`

## 1. 목적

현재 핀볼 보드를 수동 런처와 유닛 골 중심 구조에서 다수의 공이 자동 순환하며 Gold를 생산하는 방치형 구조로 변경한다. 큰 범퍼 충돌을 주 수입원으로 유지하고, 하단 골은 위치별 고정 Gold를 주는 부가 보상으로 사용한다.

## 2. 확정 요구사항

- MoonlitWorkshop 보드 아트와 Arcane 공의 테마 경계는 유지한다.
- 수동 런처 오브젝트, 투입 비용, 런처 UI와 관련 기능을 삭제한다.
- 공은 상단 중앙 자동 생성 지점에서 투입되고 회수 후 기존 재투입 지연을 거쳐 다시 투입된다.
- 기존 내부 장애물 배치를 제거하고 B형 핀 격자 배치로 다시 구성한다.
- 보드를 세로로 확대하고 위로 이동해 상단 HUD와 보드 사이 여백을 최대한 없앤다.
- 하단 골은 다섯 개이며 왼쪽부터 `30 / 50 / 100 / 50 / 30 Gold`를 지급한다.
- 일반 공과 분열 복제 공 모두 골 보상을 받는다.
- 골 보상에는 황금 공, 콤보, 범퍼 보상 배율을 적용하지 않는다.
- `FocusedPocket`은 준비 단계에서 선택한 골의 보상을 3배로 만드는 아이템으로 변경한다.
- 선택 골은 전투 중 변경할 수 없고, 다음 준비 단계에서 기존 선택을 유지하거나 변경할 수 있다.
- `TargetMagnet`, `SwapLever`, `AutoBallFeeder`와 관련 기능 및 아이템을 삭제한다.
- 유닛 소환 골에 종속된 `ChargedPin`, `OverloadBumper` 아이템도 삭제한다.
- 튜토리얼 규칙 재설계는 이번 범위에서 제외한다. 삭제되는 API를 참조해 컴파일을 깨뜨리는 연결만 분리한다.

## 3. 범위 밖

- 새로운 재화 종류 추가
- 범퍼 기본 수입, 콤보, 황금 공, 황금 범퍼의 밸런스 재설계
- 공 개수 및 재투입 속도 업그레이드 수치 변경
- 전투 및 상점 시스템 변경
- 튜토리얼 단계, 문구, 보상, 완료 조건 재설계
- 여러 보드 레이아웃을 교체하는 런타임 생성 시스템

## 4. 씬 구성

### 4.1 보드 크기

현재 측정값은 다음과 같다.

- 카메라 세로 범위: 약 `-6.515 .. 6.485`
- 상단 HUD 하단: 약 `y = 5.2`
- BoardVisual 상단: 약 `y = 4.08`
- HUD와 BoardVisual 사이 간격: 약 `1.12`

보드의 가로 폭은 유지한다. `ArcaneBoard`와 그 하위 물리 오브젝트를 세로 방향으로 약 12% 확대하고 위로 이동해 BoardVisual 상단을 HUD 하단의 약 `0.05` 월드 유닛 이내에 맞춘다. 하단 골 입구 위치는 기존 BoardVisual 하단과 최대한 같은 높이를 유지한다. 최종 수치는 Scene View와 Game View에서 외곽 벽, 골 슬롯, UI 겹침을 확인하며 미세 조정한다.

### 4.2 제거 대상 씬 오브젝트

- `/Pinball /ArcaneBoard/Launcher` 전체 계층
- 상단 UI의 비활성 `Btn_Launch`와 투입 비용 텍스트
- 기존 내부 범퍼, 작은 핀, 자석, 반사판 배치
- 기존 4개 유닛 골과 좌우 OutZone

`AutoBallSpawnPoint`, 공 풀, 보드 배경, 글로우, 외곽 벽은 유지하되 새 크기와 배치에 맞춰 위치 및 크기를 조정한다.

### 4.3 B형 핀 격자

배치는 씬에 직접 저장한다. 아래 좌표는 보드 내부의 왼쪽 아래를 `(0, 0)`, 오른쪽 위를 `(1, 1)`로 본 정규화 기준이며, 실제 월드 좌표는 MoonlitWorkshop 스프라이트와 콜라이더 중심에 맞춰 조정한다.

| 행 | 오브젝트 | 정규화 위치 |
|---|---|---|
| 투입 | AutoBallSpawnPoint | `(0.50, 0.95)` |
| 상단 | 특수 범퍼 | `(0.50, 0.82)` |
| 핀 1 | 작은 핀 4개 | `(0.25, 0.70)`, `(0.42, 0.68)`, `(0.58, 0.68)`, `(0.75, 0.70)` |
| 범퍼 | 일반 범퍼 2개 | `(0.36, 0.55)`, `(0.64, 0.55)` |
| 핀 2 | 작은 핀 2개 | `(0.17, 0.56)`, `(0.83, 0.56)` |
| 핀 3 | 작은 핀 4개 | `(0.25, 0.43)`, `(0.42, 0.41)`, `(0.58, 0.41)`, `(0.75, 0.43)` |
| 하단 범퍼 | 스피너 외형의 큰 범퍼 2개 | `(0.31, 0.30)`, `(0.69, 0.30)` |
| 핀 4 | 작은 핀 3개 | `(0.18, 0.18)`, `(0.50, 0.20)`, `(0.82, 0.18)` |
| 골 | 골 5개 | X 중심 `0.10`, `0.30`, `0.50`, `0.70`, `0.90` |

총 구성은 특수 범퍼 1개, 일반 범퍼 2개, 스피너 외형 큰 범퍼 2개, 작은 핀 13개, 골 5개다. 스피너는 마그넷이 아니며 일반 큰 범퍼처럼 반발과 Gold 보상을 제공한다. 작은 핀은 직접 Gold를 지급하지 않고 경로 분산 역할만 한다.

외곽 벽은 공이 확대된 보드 밖으로 빠져나가지 않도록 새 BoardVisual 경계에 맞춘다. 골 다섯 개는 MoonlitWorkshop 보드 하단의 다섯 슬롯과 시각적으로 일치하게 같은 너비로 배치한다.

## 5. 골 보상 모델

`PinballGoal`은 유닛 데이터 대신 직렬화된 `baseGoldReward`를 가진다. 씬에서 X 위치 순으로 `30`, `50`, `100`, `50`, `30`을 설정한다.

보상 공식은 다음 하나만 사용한다.

```text
goalReward = max(0, baseGoldReward) × (focused ? 3 : 1)
```

공이 골 트리거에 들어오면 다음 순서를 따른다.

1. 골과 공 참조가 유효한지 확인한다.
2. `PinballGoalController`에서 해당 골이 FocusedPocket 대상인지 확인한다.
3. `BattleManager.AddGold(goalReward)`를 호출한다.
4. 실제 지급액을 표시하는 골 연출과 Gold 피드백을 실행한다.
5. 골 보상 이벤트를 발행한다.
6. 공을 풀로 반환하고 기존 자동 재투입 예약을 적용한다.

복제 공도 같은 보상을 지급하지만 복제 공은 기존 규칙대로 영구 공 재투입 예약을 만들지 않는다. 황금 공 여부, 콤보, 큰 범퍼 충돌 횟수는 골 보상 공식에 들어가지 않는다.

## 6. FocusedPocket

`FocusedPocket`의 `value1`은 보상 배율 `3`으로 사용하고 설명을 새 동작에 맞게 변경한다. 골 너비 증가 및 다른 골 너비 감소 값은 제거한다.

아이템을 보유하지 않은 상태에서는 골 클릭이 보상 선택을 바꾸지 않는다. 아이템 보유 상태에서는 준비 단계에만 골 클릭을 허용한다. 선택은 새 런에서 비어 있는 상태로 시작하며, 한 번 선택하면 다음 준비 단계까지 유지된다. 준비 단계에서는 다른 골을 클릭해 선택을 변경할 수 있다.

선택 골의 Rune 또는 별도 마스크 글로우를 활성화해 3배 적용 위치를 항상 확인할 수 있게 한다. 전투 중 클릭은 선택을 변경하지 않는다.

- `ItemData.json`의 `auto_ball_feeder`, `target_magnet`, `swap_lever`, `charged_pin`, `overload_bumper`

### 7.2 단순화

- `PinballManager`: 런처 이벤트·프로퍼티·필드·빈 메서드, 투입 비용 초기화, 마그넷 적용, 골 유닛 이벤트 제거
- `Pinball`: TargetMagnet 호출 및 사용 횟수 상태 제거
- `PinballItemModifiers`: 삭제 아이템 필드와 분기 제거, FocusedPocket 배율만 유지
- `PinballGoal`: `BattleUnitSpawnData`, 교환, 골 너비 변경 제거; Gold 보상과 선택 표시 추가
- `PinballGoalController`: 위치 정렬, 선택 골, FocusedPocket 보유 여부와 배율만 관리
- 튜토리얼: 삭제된 런처 비용 및 유닛 골 API에 대한 구독과 호출만 분리하며 새 튜토리얼 규칙은 만들지 않음

`PinballMotionMath`의 속도 제한과 범퍼 반사 계산은 공과 범퍼에서 계속 사용하므로 유지한다. 런처 스프링 압축 계산만 제거한다.

## 8. 이벤트와 피드백

기존 유닛 골 이벤트는 정수 지급액과 골 위치를 전달하는 골 보상 이벤트로 대체한다. 프로토타입 메트릭과 추후 튜토리얼이 구체적인 `BattleManager` 내부 구현에 의존하지 않고 골 결과를 관찰할 수 있게 한다.

골 피드백은 다음을 포함한다.

- 골의 기존 Moonlit 링·스파크 연출
- 지급 금액 표시
- FocusedPocket 선택 골의 지속 글로우
- 3배 적용 시 기본 골보다 강한 펄스

## 9. 오류 처리

- 음수 골 보상은 `0`으로 제한한다.
- 등록되지 않은 골이나 비활성 공은 Gold를 지급하지 않는다.
- FocusedPocket 아이템이 없거나 준비 단계가 아니면 선택 변경 요청을 무시한다.
- 선택 골이 씬에서 제거되면 선택을 비운다.
- 골 다섯 개의 순서는 등록 시 월드 X 좌표로 정렬한다.
- 필수 씬 참조가 없으면 명확한 오류 로그를 남기고 해당 연출만 건너뛰며 공 회수와 경제 처리는 유지한다.

## 10. 테스트 및 완료 조건

### 단위 테스트

- 일반 골 보상 계산
- FocusedPocket 선택 골의 3배 계산
- 비선택 골은 기본 금액 유지
- 황금 공과 콤보 상태가 골 보상에 영향을 주지 않음
- 복제 공도 골 보상을 지급함
- 준비 단계 밖에서 선택 변경이 거부됨
- 삭제 아이템이 아이템 카탈로그에 없음

### 씬/EditMode 검증

- `PinballGoal`이 정확히 5개 존재함
- X 순서 보상이 `30 / 50 / 100 / 50 / 30`임
- Launcher 및 마그넷 컴포넌트가 씬에 없음
- B형 배치가 특수 범퍼 1, 일반 범퍼 2, 스피너 범퍼 2, 작은 핀 13으로 구성됨
- AutoBallSpawnPoint가 보드 상단 중앙에 있음
- BoardVisual 상단과 HUD 하단 간격이 `0.05` 월드 유닛 이내임
- 모든 보드 스프라이트는 MoonlitWorkshop, 공 스프라이트와 공 전용 효과는 Arcane 경계를 유지함

### 실행 검증

- Unity 스크립트 재컴파일 오류 0개
- 관련 EditMode 테스트 통과
- Game View에서 HUD와 보드가 겹치지 않고 눈에 띄는 상단 공백이 없음
- 여러 공과 복제 공이 보드 내부에서 안정적으로 순환함
- 각 골 진입 시 정확한 Gold가 한 번만 지급됨
- FocusedPocket 선택 표시와 3배 지급이 일치함

튜토리얼 플레이 검증은 이번 완료 조건에 포함하지 않는다.
