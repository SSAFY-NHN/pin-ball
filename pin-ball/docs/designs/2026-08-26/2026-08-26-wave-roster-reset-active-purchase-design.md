# 웨이브별 아군 초기화·전투 중 구매 설계

## 1. 목적

각 웨이브를 아군 0명과 기본 구매 상태에서 시작하도록 전투 흐름을 변경한다. 유닛 구매는 전투가 활성화된 동안에만 허용하고, 아군 보유 여부와 관계없이 웨이브를 시작할 수 있게 한다.

이번 작업은 웨이브별 전력 초기화만 다룬다. 준비 단계 타이머, 유닛 레벨 업그레이드와 핀볼 경제 문제는 후속 마일스톤으로 남긴다.

## 2. 확정 규칙

- 새 런은 아군 0명으로 시작한다.
- 아군이 없어도 현재 웨이브를 시작할 수 있다.
- 일반 유닛 구매는 `EWaveState.Active`에서만 가능하다.
- 전술 증원권을 사용한 무료 구매도 `EWaveState.Active`에서만 가능하다.
- `Pending`, `Resolving`, `Victory`, `Defeat`에서는 유닛을 구매할 수 없다.
- 웨이브 종료 시 살아 있는 아군을 포함한 모든 아군을 풀로 회수한다.
- 웨이브 종료 시 유닛별 구매 횟수를 0으로 초기화한다.
- 웨이브 종료 시 증가한 구매 가격을 각 유닛의 기본 가격으로 복구한다.
- 웨이브 종료 시 모든 유닛의 출격 쿨다운을 초기화한다.
- 다음 웨이브와 같은 웨이브 재도전은 모두 아군 0명에서 시작한다.
- 골드는 웨이브 사이에 유지한다.
- 전술 증원권 보유 상태는 웨이브 사이에 유지한다.
- 최종 승리와 최종 패배에서도 모든 아군을 회수한다.

## 3. 새 런 초기화

`UnitManager.InitializeNewRun`은 기존 풀과 로스터를 초기 상태로 정리한 뒤 기본 아군을 자동 배치하지 않는다. 씬에 활성 상태로 남아 있는 아군 풀 개체가 있다면 회수해 로스터와 화면을 일치시킨다.

`UnitPurchaseController`는 새 런에서 모든 구매 횟수와 쿨다운을 초기 상태로 가진다. 시작 골드와 핀볼 경제 초기화 규칙은 변경하지 않는다.

## 4. 웨이브 시작 조건

`BattleManager.CanStartCurrentWave`와 `TryStartWave`에서 현재 아군 보유 조건을 제거한다. 다음 조건만 만족하면 웨이브를 시작할 수 있다.

- 런이 초기화됨
- 현재 상태가 `Pending`
- 준비 행동이 잠기지 않음
- 현재 웨이브 데이터가 유효함
- `UnitManager`가 존재함

적 Spawn 실패 시 기존 오류 처리와 `Pending` 상태 유지 규칙을 보존한다. 아군이 없다는 이유로 웨이브 시작을 거부하지 않는다.

## 5. 구매 가능 상태

구매 가능 여부의 상태 검증은 `BattleManager`가 소유한다. `CanPurchaseAlly`와 `TryPurchaseAlly`는 `State == EWaveState.Active`가 아니면 즉시 실패한다.

이 검증은 다음 구매 경로에 공통 적용한다.

- 골드를 사용한 일반 구매
- 전술 증원권을 사용한 무료 구매
- 전사, 궁수, 마법사와 창병

비활성 상태에서 실패한 구매는 다음 값을 변경하지 않는다.

- 골드
- 전술 증원권
- 유닛별 구매 횟수
- 다음 구매 가격
- 출격 쿨다운
- 아군 로스터와 풀 상태

기존 골드 부족, 생존 아군 상한, 출격 쿨다운과 Spawn 실패 불변 조건은 유지한다.

## 6. 웨이브 종료 초기화 시점

방어선 파괴로 결과가 결정되면 기존 흐름대로 즉시 중복 판정을 막고 전투를 정지한다. 결과 표시 중에는 상태가 `Resolving`이므로 구매가 불가능하다.

결과 표시가 끝나 `FinishWaveResolution`이 실행될 때 다음 순서로 정리한다.

1. 기존 `UnitManager.ResolveWaveResult` 경로로 적과 모든 아군을 풀에 회수한다.
2. 아군 로스터가 0명인지 보장한다.
3. `UnitPurchaseController`의 모든 구매 횟수를 0으로 초기화한다.
4. 모든 출격 쿨다운 만료 시각을 초기화한다.
5. 구매 UI 갱신 이벤트를 한 번 발행한다.
6. 기존 정책으로 다음 상태를 `Pending`, `Victory` 또는 `Defeat`로 전환한다.

초기화는 클리어, 실패, 최종 승리와 최종 패배에 공통 적용한다. 같은 웨이브 재도전에서도 예외를 두지 않는다.

구매 가격은 별도 저장값을 직접 변경하지 않는다. 기존 비용 계산이 구매 횟수를 사용하므로 횟수 0 이후 기본 가격을 반환해야 한다.

## 7. 유지 상태

다음 런 상태는 웨이브 초기화 대상이 아니다.

- 현재 골드
- 전술 증원권 보유 여부
- 핀볼 생산 업그레이드
- 아군 공용 공격력 업그레이드
- 방어선 HP 업그레이드
- 아이템과 상점 상태
- 남은 기회
- 현재 웨이브 인덱스
- 프로토타입 지표

유닛의 개별 생존 상태, 현재 HP, 마나, 상태 효과와 공격 대상은 풀 회수 과정에서 기존 유닛 초기화 경로를 사용해 제거한다.

## 8. UI

구매 패널은 현재 구매 API 결과를 사용한다.

- `Active`: 기존 골드·인원·쿨다운 규칙에 따라 버튼 활성화
- `Pending`, `Resolving`, `Victory`, `Defeat`: 모든 유닛 구매 버튼 비활성화
- 웨이브 종료 초기화 후 각 카드의 구매 횟수 0, 기본 가격과 쿨다운 0 표시
- 전술 증원권 보유 표시는 유지하되 `Active` 전까지 사용 불가

새 UI, 준비 타이머와 별도 잠금 안내 문구는 추가하지 않는다. 기존 버튼 비활성 상태와 현재 상태 표시를 재사용한다.

## 9. 테스트와 검증

EditMode 테스트는 다음을 증명한다.

- 새 런의 아군 로스터가 0명이다.
- 아군 0명 상태에서 웨이브 시작 조건이 참이다.
- `Pending`, `Resolving`, `Victory`, `Defeat`에서 일반 구매가 실패한다.
- 비활성 상태에서 무료 구매가 실패하고 전술 증원권이 유지된다.
- `Active`에서 기존 조건을 만족한 일반·무료 구매가 성공한다.
- 구매 성공 후 해당 유닛의 구매 횟수, 가격과 쿨다운이 변경된다.
- 웨이브 클리어 후 모든 아군이 회수되고 세 구매 상태가 초기화된다.
- 웨이브 실패 후 같은 웨이브 재도전에서도 동일하게 초기화된다.
- 최종 승리와 최종 패배에서도 모든 아군이 회수된다.
- 초기화 후 첫 구매 비용이 기본 가격이고 남은 쿨다운이 0이다.
- 웨이브 종료 전후 골드와 전술 증원권이 변하지 않는다.
- 회수된 유닛이 다음 Spawn에서 기존 초기화 상태로 재사용된다.

씬 검증은 다음을 확인한다.

- 새 런 시작 시 활성 아군이 남지 않는다.
- 아군이 없어도 웨이브 시작 버튼이 활성화된다.
- 준비·결과 상태에서 네 구매 카드가 비활성화된다.
- 다음 웨이브 시작 전 카드가 기본 비용과 쿨다운 0을 표시한다.

구현 후 관련 EditMode 테스트, C# 컴파일과 허용된 Unity 검증을 실행한다.

## 10. 비범위

- 준비 단계 타이머
- 준비 단계 핀볼 생산과 골드 정책
- 유닛 레벨과 레벨 업그레이드
- 출전 덱 편성
- 구매 비용·증가 배율·쿨다운 수치 변경
- 골드 초기화 또는 웨이브별 골드 예산
- 전술 증원권 초기화
- 웨이브 공세와 적 조합 변경
- 새 UI와 튜토리얼
- 외부 패키지 추가
- 요청과 무관한 리팩터링
