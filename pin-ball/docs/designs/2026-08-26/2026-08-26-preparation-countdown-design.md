# 60초 전투 준비 제한 설계

## 목표

기존 게임 경제와 단계별 행동을 유지하면서 `Pending` 준비 단계에 최대 60초 제한을 추가한다.

## 확정 규칙

- 새 런 시작, 다음 웨이브 진입, 같은 웨이브 재시도 때 준비 시간이 60초로 초기화된다.
- 준비 중 기존 전투 시작 버튼을 누르면 즉시 전투를 시작한다.
- 남은 시간이 0초가 되면 현재 웨이브를 자동으로 시작한다.
- Gold는 초기화하지 않으며 성공·실패와 웨이브 사이에 유지한다.
- 핀볼과 Gold 생산의 기존 상태별 동작은 변경하지 않는다.
- 기존 강화, 아이템 구매, 유닛 구매 가능 단계도 변경하지 않는다.
- 성공·실패 모두 아군을 제거하는 기존 규칙을 유지한다.
- 최종 `ResultPanel`에서 핀볼을 정지하는 기존 규칙을 유지한다.
- 튜토리얼 오버레이가 활성화된 동안 준비 타이머를 멈추고, 종료 후 60초부터 시작한다.
- 일시정지에서는 타이머가 멈추며 게임 배속은 준비시간 길이에 영향을 주지 않는다.
- 10초 이하에서 버튼 문구를 강조하고 5초 이하에서 매초 경고음을 재생한다.
- 핀볼 발사대의 마우스 직접 조작은 비활성화하고 자동 핀볼 순환만 유지한다.

## 경제 방향

전투를 오래 유지해 핀볼 Gold를 더 얻는 행동은 허용된 전략이다. 지속 증원 압박이 수익에 대한 위험으로 작동한다. 초기 밸런스 목표는 첫 웨이브 수익으로 기본 유닛 4~6명, 초반 매 웨이브 강화 1회, 중반 2웨이브당 강화 1회, 핀볼 강화 1회당 60초 실수익 약 15~20% 증가다. 실제 수치는 플레이 측정 후 이 목표에 맞춘다.

## 구조

순수 C# `PreparationCountdown`이 제한 시간, 남은 시간과 한 번뿐인 만료 신호를 소유한다. `BattleManager`는 `Pending`에서만 카운트다운을 진행하고 만료 신호를 받으면 기존 `TryStartWave`를 호출한다. `WavePanel`은 기존 시작 버튼 문구에 올림한 남은 초를 표시한다.

## 예외 처리

- `Pending` 밖에서는 시간이 감소하지 않는다.
- 수동 시작 이후 카운트다운은 더 이상 진행하지 않는다.
- 자동 시작 시 적 생성 실패 등으로 `TryStartWave`가 실패해도 매 프레임 재호출하지 않는다. 시작 버튼은 남아 수동 재시도를 허용한다.
- `Time.deltaTime <= 0`이면 시간이 감소하지 않는다.

## 검증

- 카운트다운 초기값, 감소, 0 고정과 단일 만료 신호를 EditMode 테스트로 고정한다.
- `BattleManager`가 `Pending`에서만 카운트다운을 진행하고 만료 시 기존 시작 경로를 호출하는지 검증한다.
- 버튼 표시용 초 계산이 60, 59, 1, 0 경계에서 올림되는지 검증한다.
