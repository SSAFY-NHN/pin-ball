# 기지 전선 밀어내기 스킬 설계

## 1. 목적

전투 중 플레이어가 위기 순간에 전선을 한 번 복구할 수 있는 첫 기지 액티브 스킬을 추가한다. 스킬은 적에게 피해를 주지 않고 적 기지 방향으로 밀어내며, 기존 유닛 역할과 구매 판단을 대체하지 않는 보조 수단으로 제한한다.

이번 작업은 기지 스킬 1종의 전투 규칙, 상태, UI와 검증만 다룬다. 핀볼 콤보·잭팟 충전, 스킬 강화와 다중 스킬 선택은 후속 범위로 남긴다.

## 2. 확정 규칙

- 스킬 이름은 프로토타입 기준 `전선 밀어내기`로 한다.
- 각 웨이브에서 최대 1회만 사용할 수 있다.
- 웨이브 전투가 시작되면 잠긴 상태로 시작한다.
- `EWaveState.Active` 전투 시간이 30초에 도달하면 사용할 수 있다.
- 30초는 기존 공세 시간표와 같은 게임 시간 기준이다. 2배속에서는 현실 시간 약 15초 후 해금된다.
- 해금 후 플레이어가 씬 배치 버튼을 눌러 수동 발동한다.
- 살아 있고 풀에 반환되지 않은 적 중 넉백 가능한 대상이 1명 이상 있어야 성공한다.
- 성공한 모든 적을 아군 방어선에서 적 방어선으로 향하는 방향으로 3 Unity 유닛만큼 이동시킨다.
- 피해, 기절과 감속은 적용하지 않는다.
- 넉백 면역 적은 위치와 방어선 도달 상태 모두 유지한다.
- 넉백에 성공한 적은 방어선 도달 상태와 방어선 공격 대상을 해제하고 정상 이동·타겟 탐색을 재개한다.
- 실제로 넉백된 적이 1명 이상일 때만 해당 웨이브의 사용권을 소비한다.
- 적이 없거나 모든 적이 넉백 면역이면 요청은 실패하며 사용권을 유지한다.
- 전장 표시 경계 밖으로 밀리는 것은 허용한다. 위치를 경계 안으로 강제 보정하지 않는다.
- 다음 웨이브에서는 다시 잠긴 상태와 경과 시간 0으로 초기화한다.

## 3. 상태 모델과 시간

기지 스킬의 웨이브 한정 상태는 다음 세 단계다.

```text
Locked -> Ready -> Used
```

- `Locked`: 현재 웨이브의 `Active` 경과 시간이 30초 미만이다.
- `Ready`: 30초 이상이며 아직 성공적으로 사용하지 않았다.
- `Used`: 이번 웨이브에서 적어도 한 명에게 실제 넉백을 적용했다.

`Pending`, `Resolving`, `Victory`, `Defeat`에서는 시간이 흐르지 않고 사용 요청을 거부한다. 일시정지에서는 `Time.deltaTime`이 0이므로 해금 시간이 진행되지 않는다. 게임 배속은 기존 전투와 동일하게 `Time.deltaTime`에 반영한다.

웨이브가 시작될 때 상태와 경과 시간을 초기화한다. 웨이브 결과가 결정되거나 표시되는 동안 추가 사용을 차단하고, 다음 웨이브 시작 때 새로운 1회 사용 주기를 시작한다.

## 4. 구조와 책임

### `BaseKnockbackSkillController`

순수 C# 전투 도메인 객체로 구현한다.

- 30초 해금 시간
- 현재 웨이브 경과 시간
- `Locked`, `Ready`, `Used` 상태
- 웨이브 시작 초기화
- `Active` 시간 진행
- 사용 가능 조건과 성공 후 사용 처리

Unity 씬, 버튼, 적 목록과 직접 결합하지 않는다. `BattleManager`가 전달한 시간과 실제 적용 성공 여부만 사용한다.

### `BattleManager`

스킬 사용의 공통 진입점과 전투 상태 검증을 소유한다.

- 웨이브 시작 시 스킬 컨트롤러 초기화
- `Active` 동안 게임 시간 전달
- 상태와 생존 적 존재 여부를 포함한 사용 가능 조회 제공
- UI 사용 요청을 받고 조건을 다시 검증
- `UnitManager`에 실제 넉백 적용 요청
- 적용 성공 수가 1명 이상일 때만 컨트롤러를 `Used`로 전환
- 상태 변화와 표시 갱신에 필요한 최소 이벤트 발행

공세 시간표와 스킬 해금 시간은 같은 `Time.deltaTime` 흐름을 사용하지만 서로의 내부 상태를 공유하지 않는다.

### `UnitManager`

현재 활성 적 로스터와 방어선 참조를 사용해 효과를 적용한다.

- 활성 적 스냅샷 생성
- 죽은 적, 풀에 든 적과 null 제외
- 아군 방어선에서 적 방어선으로 향하는 고정 방향 계산
- 각 대상에게 3 유닛 넉백 시도
- 실제 적용된 적 수 반환

방향은 적의 현재 위치에서 적 방어선을 바라보는 벡터로 계산하지 않는다. 적이 적 방어선을 넘어간 경우 방향이 반전되는 문제를 막기 위해 두 방어선의 배치 방향을 기준으로 고정한다.

### `UnitBase`

기존 `ApplyKnockback` 호출부는 유지한다. 기존 동작을 깨지 않으면서 넉백 성공 여부와 선택적인 방어선 상태 해제를 표현할 수 있는 좁은 API를 추가한다.

- 넉백 면역이면 실패하고 아무 상태도 변경하지 않음
- 유효한 방향과 양수 거리에서만 적용
- 성공 시 위치 이동
- 기지 스킬 경로에서는 방어선 도달 상태와 현재 방어선 공격 대상을 해제
- 일반 유닛 스킬의 기존 넉백 의미는 변경하지 않음

## 5. UI와 피드백

Game 씬의 기존 Canvas 전투 HUD에 `BaseSkillPanel`을 사전 배치하고 Inspector 참조로 연결한다. 런타임 UI 자동 생성은 사용하지 않는다.

- 버튼 표시 이름: `전선 밀어내기`
- 준비 상태: `대기`
- 전투 시작 후 30초 전: 올림한 남은 초 표시, 버튼 비활성
- 30초 이후: `사용 가능`, 버튼 활성
- 준비 완료지만 적이 없음: `사용 가능` 표시는 유지하고 버튼만 비활성
- 성공 사용 후: `사용 완료`, 버튼 비활성
- 다음 웨이브 시작: 다시 남은 시간 표시

표시는 상태 변화와 표시할 정수 초가 바뀔 때만 갱신한다. 매 프레임 UI 계층을 재구성하지 않는다. 해금 순간에는 기존 UI 표현 방식과 어울리는 짧은 강조 효과를 사용한다.

첫 구현에서는 신규 이미지, 사운드와 전장 VFX를 추가하지 않는다. 넉백 이동과 버튼 상태 피드백으로 가독성을 확인하고, 부족하면 별도 후속 마일스톤으로 다룬다.

## 6. 경계 밖 이동과 복귀 보장

넉백 결과를 `BattleAreaBounds` 안으로 제한하지 않는다. 표시 전장 밖으로 잠시 이동한 적도 기존 이동 목표와 전투 갱신을 유지해야 한다.

- 넉백 성공 시 방어선 공격 상태를 해제한다.
- 적의 전투 활성 상태와 로스터 등록은 유지한다.
- 다음 갱신부터 기존 적 이동·타겟 탐색 경로를 사용한다.
- 콜라이더나 방어선 트리거 때문에 외곽에 고립되지 않는지 씬과 EditMode 경계 테스트로 확인한다.
- 적 기지 뒤쪽까지 이동해 복귀 방향이 모호해지는 문제는 고정된 방어선 방향과 3 유닛 거리 제한으로 방지한다.

실제 씬 배치에서 3 유닛 이동이 충돌 지형 너머로 적을 보내 복귀를 막는다면, 임의 위치 보정이나 텔레포트 우회를 추가하지 않고 사용자에게 씬 구조와 재현 결과를 보고한다.

## 7. 실패와 불변 조건

다음 경우 사용 요청은 실패하고 상태를 `Ready`로 유지한다.

- 현재 상태가 `Active`가 아님
- 전투 경과 시간이 30초 미만
- 이미 이번 웨이브에서 사용함
- `UnitManager` 또는 방어선 방향을 구할 수 없음
- 살아 있는 활성 적이 없음
- 모든 적이 넉백 면역이거나 유효하지 않음

실패 시 골드, 전술 증원권, 구매 횟수, 유닛 쿨다운, 적 HP, 공세 시간표와 웨이브 상태를 변경하지 않는다. 중복 버튼 입력도 같은 검증을 통과해야 하며 두 번째 성공을 만들 수 없다.

## 8. 테스트와 검증

EditMode 테스트는 다음을 증명한다.

- 웨이브 시작 직후 `Locked`와 경과 시간 0이다.
- 29.99초에는 잠기고 30초에는 `Ready`다.
- `Active`가 아니면 시간이 진행되지 않고 사용이 실패한다.
- 게임 시간 입력이 그대로 누적되어 기존 배속 흐름과 일치한다.
- 적이 없거나 전부 면역이면 사용권이 유지된다.
- 일반 적이 하나라도 넉백되면 `Used`가 된다.
- 여러 생존 적에게 각각 정확히 3 유닛 넉백이 적용된다.
- 죽은 적, 풀에 든 적과 null은 제외된다.
- 면역 적은 위치와 방어선 상태가 유지된다.
- 방어선을 공격 중인 비면역 적은 도달 상태가 해제된다.
- 넉백된 적은 다음 갱신에서 이동·타겟 탐색을 재개한다.
- 한 웨이브의 두 번째 사용은 실패한다.
- 다음 웨이브에서 다시 `Locked`와 0초로 시작한다.
- 실패 요청은 다른 전투·경제 상태를 변경하지 않는다.

씬 검증은 다음을 확인한다.

- Game 씬에 기지 스킬 패널과 버튼이 각각 1개 존재한다.
- 버튼, 상태 문구와 컨트롤러 참조가 Inspector에 연결되어 있다.
- 준비, 잠금, 준비 완료, 적 없음과 사용 완료 상태에서 표시와 interactable 값이 일치한다.
- 런타임 UI 자동 생성과 Missing Script/Reference가 없다.
- 넉백으로 화면 경계를 벗어난 적이 정상적으로 전장에 복귀한다.

구현 후 관련 EditMode 테스트, 전체 EditMode, C# 컴파일, 씬 참조 검사와 가능한 Unity 직접 검증을 실행한다. 기존 전체 EditMode 실패 5개는 기준선과 비교해 새 회귀 여부를 구분한다.

## 9. 비범위

- 직접 피해, 기절, 감속과 방어력 감소
- 핀볼 콤보·잭팟·충전 게이지 연동
- 반복 쿨다운 또는 웨이브당 다중 사용
- 다중 기지 스킬과 스킬 선택 UI
- 기지 스킬 강화, 레벨과 영구 성장
- 신규 이미지, 사운드와 전장 VFX
- 전장 경계 강제 보정
- 유닛 구매, 경제, 공세와 웨이브 조합 변경
- 외부 패키지 추가와 요청 없는 리팩터링
