# 아케인 핀볼 게임 아트 제작 지침서

## 1. 문서 목적

이 문서는 Unity 6, URP 2D Renderer 기반 PC WebGL 게임의 아트 리소스를 제작하기 위한 기준이다.

게임 기능은 이미 구현되어 있다. 이번 작업의 목적은 게임 구조를 새로 설계하는 것이 아니라, 첨부된 두 장의 목표 화면을 기준으로 실제 프로젝트에 적용할 수 있는 일관된 아트 리소스를 제작하는 것이다.

처음부터 전체 리소스를 일괄 생성하지 않는다. 먼저 픽셀 밀도, 팔레트, 캐릭터 크기, UI 규격을 확정한 뒤 대표 화면 한 세트를 제작하고 승인 후 확장한다.

## 2. 최종 기준 이미지

첨부된 두 이미지를 최종 아트 방향의 기준으로 사용한다.

- **이미지 1 — 전투 단계:** 핀볼 장치가 화면 밖으로 퇴장하고 전투 영역이 전체 폭으로 확장된 상태
- **이미지 2 — 준비 단계:** 소등된 전투 무대와 오른쪽 핀볼 소환 장치가 함께 보이는 상태

두 이미지는 다음 항목의 기준이다.

- 전체 분위기와 색상 관계
- UI 재질과 테두리 스타일
- 배경과 캐릭터의 디테일 비율
- 캐릭터와 적의 화면상 크기
- 선택적 발광의 강도와 위치
- 준비 단계와 전투 단계의 시각적 대비
- 핀볼 장치의 형태와 전통적인 스프링 발사 구조
- 상단 10웨이브 진행 표시 방식

두 이미지를 픽셀 단위로 그대로 복제할 필요는 없다. 실제 결과물은 프로젝트의 PPU, Sprite 크기, RectTransform, 카메라 크기에 맞춰야 한다. 단, 임의로 더 고밀도·고해상도화하거나 과도하게 저해상도화하지 않는다.

이전에 검토한 다음 방향은 최종 기준에서 제외한다.

- 개별 나뭇잎·돌·벽돌이 가득한 고밀도 픽셀 배경
- 밝은 산과 석양으로 배경 자체가 바뀌는 전투 화면
- `480×270`을 과도하게 굵은 픽셀로 표현한 초저밀도 시안
- 해골·사슬·촛불·복잡한 조각이 과도한 프레임

## 3. 핵심 콘셉트

최종 콘셉트는 다음과 같다.

> 중간 밀도의 다크 픽셀 판타지 + 선택적으로 강한 아케인 핀볼 VFX

보조 설명:

> 동화풍 픽셀 판타지의 제작 방식에 흑철·석재·황동 재질과 청록·보라색 마법 조명을 결합한다.

시각적 완성도는 모든 리소스를 복잡하게 그려서 만드는 것이 아니다. 차분한 비발광 영역을 충분히 확보하고, 핀볼·룬·투사체·충돌·선택 상태에만 발광을 집중해 만든다.

## 4. 픽셀 밀도 기준

픽셀 밀도는 첨부된 두 최종 이미지의 중간 밀도를 시각적 기준으로 삼는다.

- 캐릭터는 직업, 무기, 얼굴 방향이 식별될 정도의 디테일을 가진다.
- 배경은 캐릭터보다 한 단계 낮은 디테일을 사용한다.
- 나무는 큰 수관 덩어리와 일부 잎 클러스터를 사용하되 개별 잎을 빽빽하게 그리지 않는다.
- 유적은 큰 석재 면을 우선하며 모든 벽돌을 개별 묘사하지 않는다.
- 지면은 큰 명암 덩어리를 유지하고 돌, 균열, 풀을 무작위로 가득 채우지 않는다.
- UI 테두리는 재질이 느껴질 정도로 표현하되 장식 조각을 과도하게 추가하지 않는다.
- VFX 중심부는 명확한 픽셀 도형으로 만들고 부드러운 번짐은 Unity Bloom에 맡긴다.

`480×270` 같은 기준 해상도를 먼저 강제하지 않는다. 최종 PPU와 원본 Sprite 크기는 기존 프로젝트 리소스를 분석한 후 결정한다. 제작자는 첫 작업 전에 다음 정보를 확인해야 한다.

- 현재 프로젝트의 Pixels Per Unit
- 전투 캐릭터의 실제 화면상 높이
- 핀볼, 범퍼, 골의 실제 Sprite 크기
- Canvas 기준 해상도와 Canvas Scaler 설정
- Pixel Perfect Camera 사용 여부
- Sprite Atlas 및 애니메이션 프레임 규격

## 5. 두 화면은 같은 공간이다

준비 화면과 전투 화면은 서로 다른 배경을 사용하지 않는다.

- 숲, 지평선, 나무, 유적, 바닥은 동일한 장소다.
- 준비 단계에서는 오른쪽 일부가 핀볼 장치에 가려진다.
- 전투 단계에서는 핀볼 장치가 오른쪽으로 슬라이드 아웃하고, 가려졌던 전투 배경이 드러난다.
- 전투 시작 시 태양, 석양, 산, 새로운 길 같은 배경 요소를 추가하지 않는다.
- 배경의 시간대와 기본 청록·남색 색조는 유지한다.

따라서 배경은 처음부터 전투 단계의 전체 가로 폭을 기준으로 제작하고, 준비 단계에서는 UI와 핀볼 장치가 오른쪽을 가리는 구조가 적합하다.

권장 배경 분리:

1. 후경 하늘과 먼 숲 실루엣
2. 중경 나무·관목·유적
3. 전투 바닥
4. 제한적인 전경 가장자리 장식
5. 별도 조명 및 안개 마스크

## 6. 준비 단계 화면

준비 단계에서는 핀볼이 시각적 주인공이다.

### 전투 영역

- 이전 웨이브의 적은 표시하지 않는다.
- 보유 아군은 소등된 무대에서 대기한다.
- 아군의 실루엣, 직업, 무기는 식별할 수 있어야 한다.
- 전투 배경은 어두운 청록·남색으로 낮춘다.
- 준비 단계의 드래그 배치와 합성을 고려해 캐릭터 주변의 바닥이 복잡하지 않아야 한다.
- 유닛이 UI 아래에 가려지지 않도록 안전 영역을 확보한다.

### 핀볼 영역

- 화면 오른쪽에 독립적인 소환 장치처럼 배치한다.
- 흑철, 어두운 석재, 낡은 황동을 기본 재질로 사용한다.
- 핀, 범퍼, 골, 레일이 배경과 명확히 구분되어야 한다.
- 핀볼 공은 청록색 중심광과 보라색 보조광을 사용할 수 있다.
- 발사구는 오른쪽 하단의 전통적인 핀볼 슈터 레인으로 구성한다.
- 공이 스프링 위에 놓이고, 코일 스프링과 플런저 손잡이가 물리적으로 읽혀야 한다.
- 발사 레인은 오른쪽을 따라 위로 올라가 메인 필드로 진입한다.
- 첫 발사 비용은 `50G`이며 같은 준비 단계에서 `80G`, `110G`, `140G` 순으로 증가한다.
- 골드가 부족한 상태를 위한 비활성 버튼과 적색 비용 표시가 필요하다.

### 골과 소환 정보

- 공마다 유닛이 정해지는 구조가 아니다.
- 각 골인 지점에 소환할 유닛 직업이 연결된다.
- 골 자체에는 레벨 표시를 넣지 않는다.
- 각 골에는 연결된 직업을 식별할 수 있는 간단한 문장, 초상, 무기 또는 직업 룬을 사용한다.
- 선택된 골과 일반 골의 상태가 명확히 구분되어야 한다.

## 7. 전투 단계 화면

전투 단계에서는 핀볼 장치가 화면 밖으로 완전히 퇴장하고 전투가 시각적 주인공이 된다.

- 핀볼 필드, 스프링, 발사 버튼, 발사 비용을 표시하지 않는다.
- 전투 영역이 오른쪽으로 확장되어 대부분의 화면을 사용한다.
- 아군은 왼쪽, 적은 오른쪽, 중앙은 충돌과 투사체를 위한 여백으로 사용한다.
- 자동 전투 중에는 준비 단계 조작을 시각적으로 비활성화한다.
- 아군과 적의 체력바는 단순하고 얇게 표현한다.
- 캐릭터 아래에 접지 그림자를 사용한다.

전투 조명은 배경 교체가 아니다.

- 배경은 계속 어두운 청록·남색을 유지한다.
- 아군 진영, 적 진영, 중앙 교전 구역에 제한적인 금색 조명 풀을 사용한다.
- 캐릭터 가장자리 일부에 따뜻한 림라이트를 사용할 수 있다.
- 화면 전체를 금색이나 주황색으로 색보정하지 않는다.
- 강한 조명은 캐릭터와 전투 피드백을 읽히게 하는 용도에만 사용한다.

### 재질 규칙

- **흑철:** 거의 검은 남색 기반, 일부 모서리에만 차가운 하이라이트
- **석재:** 큰 면 분할 중심, 균열과 개별 벽돌은 제한
- **황동:** 연결부, 선택 상태, 중요한 버튼에만 사용
- **마법 룬:** 작은 크기에서도 읽히는 단순한 기하학 문양
- **목재:** 큰 명암 2~3단계로 표현하며 세밀한 나뭇결은 생략

## 10. 셰이더를 고려한 아트 제작

아트 리소스는 셰이더가 잘 드러날 수 있도록 제작한다.

### 아트가 담당할 요소

- 기본 형태와 실루엣
- 큰 명암 구분
- 재질을 구분하는 핵심 픽셀
- 발광 중심부의 형태
- 직업, 무기, 적 종류의 식별성
- UI 프레임의 기본 구조

### Unity가 담당할 요소

- Bloom 번짐
- 핀볼 궤적
- 속도에 따른 발광 변화
- 충돌 스파크와 파동
- 룬 펄스
- 피격 플래시
- 상태 이상 Tint
- 선택 외곽광
- 배경 안개와 부유 입자
- 준비·전투 단계 조명 전환

PNG에 넓은 Glow나 Bloom 번짐을 직접 그리지 않는다. 중심광은 선명하게 만들고 주변 번짐은 셰이더에 맡긴다.

필요한 경우 컬러 Sprite와 동일 크기의 마스크를 제작한다.

- R: 발광 영역
- G: 색상 교체 영역
- B: 특수 상태 또는 디졸브
- A: 보조 마스크

마스크 우선 대상:

- 핀볼
- 특수 범퍼
- 골과 직업 룬
- 희귀 아이템
- 선택 버튼
- 보스 경고

## 11. UI 제작 기준

### 상단 상태 표시줄

- 화면 상단에 얇게 배치한다.
- 플레이어 HP와 골드를 표시한다.
- `1/10` 형식의 텍스트 웨이브 표시는 사용하지 않는다.
- 정확히 10개의 연결된 웨이브 노드를 표시한다.
- 현재 웨이브는 크기와 테두리로 강조한다.
- 5웨이브는 첫 정예 표식을 사용한다.
- 9웨이브는 보스 직전 정예 표식을 사용한다.
- 10웨이브 노드 자체에 `goblin_king` 보스 표식을 넣는다.
- 10번 뒤에 별도의 11번째 보스 아이콘을 추가하지 않는다.

### 하단 상점·아이템 영역

- 화면 하단 가장자리에 компакт하게 배치한다.
- 상점과 보유 아이템은 같은 영역에서 탭 또는 버튼으로 전환한다.
- 두 패널을 동시에 넓게 펼치지 않는다.
- 아이템 슬롯은 일반, 선택, 비활성, 희귀 상태를 제공한다.
- 전투 중에는 시각적으로 잠긴 상태를 제공한다.

### 유닛 상세 패널

- 화면 오른쪽에서 슬라이드되는 별도 패널을 고려한다.
- 평상시에는 닫혀 있어야 한다.
- 직업, 레벨, 스킬 이름과 설명, 주요 능력치를 표시할 공간을 확보한다.
- 이 패널은 준비·전투 메인 화면을 항상 덮는 고정 패널이 아니다.

### 전직 선택 모달

- 기본 직업이 5레벨에 도달했을 때 두 상위 직업 중 하나를 선택한다.
- 선택이 완료되기 전에는 취소하거나 우회할 수 없는 모달이다.
- 두 직업 선택 카드, 직업 아이콘, 핵심 능력 설명을 위한 별도 UI 세트가 필요하다.
- 배경을 완전히 새로 만들지 않고 기존 UI 재질과 룬 체계를 유지한다.

## 12. 캐릭터 제작 기준

- 캐릭터는 배경보다 높은 디테일을 허용한다.
- 작은 화면에서도 직업과 무기가 읽혀야 한다.
- 모든 캐릭터에 상시 발광 외곽선을 넣지 않는다.
- 기본 상태는 비발광이며 스킬, 선택, 피격 순간에만 셰이더가 반응한다.
- 아군과 적은 실루엣과 색상군으로 즉시 구분되어야 한다.
- 전직한 캐릭터도 기본 직업 계열과 연결성이 느껴져야 한다.

최소 상태:

- Idle
- Walk 또는 이동
- Attack
- Hit
- Dead 또는 전투불능
- 준비 단계 선택 표시용 기준 Sprite

합성·부활·풀 재사용은 코드 동작이므로 Sprite에 영구적인 전투 상태를 그리지 않는다.

## 15. 금지 사항

- 두 기준 이미지보다 고밀도·고해상도로 임의 변경
- 과도하게 굵은 초저해상도 스타일로 변경
- 준비·전투 단계에 서로 다른 배경 사용
- 전투 시작 시 낮, 석양, 산, 새 길로 배경 교체
- 개별 잎, 돌, 벽돌, 균열을 화면 전체에 과도하게 묘사
- 모든 오브젝트의 상시 네온 외곽선
- PNG에 Bloom 번짐을 직접 그림
- 현재 프로젝트에 없는 기능성 패널 추가
- 해골, 사슬, 촛불, 조각 장식을 반복적으로 남용
- 포토리얼 재질
- 고해상도 일러스트를 축소한 가짜 픽셀아트
- 색수차, CRT 노이즈, 스캔라인 남용
- 긴 텍스트가 포함된 완성 UI 이미지를 생성해 실제 현지화를 막는 방식
- 승인 전 전체 리소스 일괄 제작

## 16. 작업 진행 절차

1. 첨부된 두 기준 이미지와 프로젝트 원본 Sprite를 분석한다.
2. 프로젝트 PPU, Canvas, 캐릭터 크기, 핀볼 크기를 확인한다.
3. 팔레트와 픽셀 밀도 샘플을 먼저 제출한다.
4. 기존 프로젝트 화면 위에 합성한 준비 단계 시안을 만든다.
5. 승인 후 개별 준비 단계 리소스를 출력한다.
6. 동일한 배경을 확장해 전투 단계 합성 시안을 만든다.
7. 조명과 VFX 중심부를 별도 레이어 또는 마스크로 분리한다.
8. Unity 적용 결과를 확인한 후 나머지 캐릭터와 UI로 확장한다.
