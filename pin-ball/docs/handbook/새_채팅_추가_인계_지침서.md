# 새 채팅 추가 인계 지침서

## 1. 문서의 역할과 우선순위

이 문서는 다음 두 문서와 함께 사용한다.

- `docs/handbook/프로젝트 지침서.md`
- `docs/handbook/아트 리소스 지침서.md`

두 기존 문서와 이 문서의 내용이 충돌하면 **이 추가 인계 지침서를 우선한다.**

현재 새 채팅의 목적은 게임 기능을 다시 설계하는 것이 아니라, 이미 구현된 기능에 맞는 아트 리소스와 셰이더 적용 계획을 순서대로 완성하는 것이다. 사용자가 명시적으로 Unity 적용을 요청하기 전에는 프로젝트 코드, 씬, 프리팹을 수정하지 않는다.

## 2. 반드시 정정할 사항

### 핀볼 골은 정확히 4개다

이전 `아트 리소스 지침서.md`의 `골 3~4종` 표현은 폐기되었고, 현재 문서에는 정확히 4종으로 반영되어 있다.

- 핀볼 보드에는 실제 공이 들어가는 골인 지점이 **정확히 4개** 있어야 한다.
- 공마다 직업이 정해지는 것이 아니라, 네 골 각각에 소환할 기본 직업이 연결된다.
- 골 자체에는 레벨이 없다.
- 네 골은 크기와 중요도가 동일해야 한다.
- 각 골에는 직업 아이콘 또는 직업 룬을 별도 Sprite로 표시할 공간이 필요하다.
- 직업 아이콘, 선택 표시, 발광은 보드 본체에 굽지 않는다.
- 골 외의 범퍼, 장식 링, 배수구가 다섯 번째 골처럼 보이면 안 된다.
- 네 골 모두 실제 핀볼 물리 경로에서 진입 가능해야 한다.

### 숫자와 텍스트는 이미지에 굽지 않는다

- 시작 골드는 `800G`다.
- 첫 발사 비용은 `50G`이며 성공할 때마다 `80G`, `110G`, `140G` 순으로 증가한다.
- 웨이브는 정확히 10개다.
- 모든 숫자, 비용, 직업명, 버튼 문구는 Unity의 동적 UI로 표시한다.
- 레퍼런스 이미지에 보이는 `750` 같은 수치를 그대로 아트에 넣지 않는다.

## 3. 확정된 시각 방향

최종 방향은 다음과 같다.

> 선명한 중간 밀도의 다크 픽셀 판타지 배경 + 흑철·석재·황동 핀볼 장치 + 선택적인 청록·보라·금색 발광

- 배경은 딥 네이비와 청록을 중심으로 유지한다.
- 핀볼 공과 주요 마력 장치는 청록색을 중심으로 사용한다.
- 룬과 특수 범퍼는 보라색을 보조색으로 사용한다.
- 성공, 보상, 중요한 선택과 전투 조명은 금색을 제한적으로 사용한다.
- 모든 오브젝트를 네온처럼 빛나게 만들지 않는다.
- 아트에는 선명한 발광 중심부만 만들고 넓은 번짐은 Unity Bloom에 맡긴다.
- 흐릿한 페인팅이나 고해상도 일러스트를 축소한 가짜 픽셀아트는 사용하지 않는다.

## 4. 배경 제작 현황

배경은 합본이 아니라 다음 네 레이어로 제작하는 방향이 확정되었다.

1. 하늘
2. 원경 산과 숲
3. 전투 바닥
4. 전경 가장자리 장식

현재 네 이미지의 아트 생성은 완료되었으나 Unity용 최종 정규화는 아직 하지 않았다.

- 하늘: `1672×941`, 불투명 RGB
- 원경 산과 숲: `1536×1024`, 알파 PNG
- 전투 바닥: `1536×1024`, 알파 PNG
- 전경 가장자리: `1536×1024`, 알파 PNG

이 해상도 차이를 무시하거나 3:2 이미지를 16:9로 비균일 확대하지 않는다. Unity 적용 전에 원본을 보존한 상태에서 공통 16:9 캔버스로 크롭·배치하고 합성 미리보기를 검수해야 한다.

배경에 대한 추가 이미지 생성은 사용자가 요청하지 않는 한 진행하지 않는다. 현재 작업 우선순위는 핀볼 리소스다.

## 5. 핀볼 보드 제작의 핵심 원칙

### 보드 본체와 동적 부품을 분리한다

핀볼 보드 베이스에는 정적인 구조만 포함한다.

보드 본체에 포함:

- 외곽 프레임
- 어두운 석재 플레이 필드
- 고정된 외곽 벽과 통로
- 오른쪽 슈터 레인
- 하단 배수·실패 영역의 고정 구조
- 비활성 상태의 골 설치 구조 4개
- 정적인 흑철, 석재, 황동 장식

별도 투명 PNG로 제작:

- 핀볼 공
- 플런저 손잡이와 움직이는 부분
- 코일 스프링의 상태 표현
- 플리퍼 또는 움직이는 반사 장치
- 작은 충돌 핀
- 일반 범퍼
- 특수 범퍼
- 골의 직업 아이콘
- 골 선택·활성·성공 효과
- 발광 룬
- 공 궤적 중심 Sprite
- 충돌 섬광과 파동

공, 플리퍼, 범퍼, 충돌 핀, 발사 손잡이가 보드 이미지에 합쳐져 있으면 최종 리소스로 승인하지 않는다.

### 골과 범퍼를 시각적으로 구분한다

- 골은 공이 들어가는 어두운 입구로 표현한다.
- 범퍼는 공을 튕겨내는 돌출된 장치로 표현한다.
- 골은 오목하고, 범퍼는 볼록해야 한다.
- 단순한 원형 황동 링을 여러 개 반복해 골과 범퍼가 혼동되는 디자인을 피한다.
- 네 골을 제외한 다른 구멍은 골처럼 강조하지 않는다.

### 기존 기능 배치를 우선한다

최종 제작 전에 현재 Unity 핀볼 화면의 스크린샷을 확인해야 한다.

- 기존 Collider와 장치의 상대적 위치를 우선한다.
- 아트 때문에 핀볼 물리 구조를 임의로 바꾸지 않는다.
- 기능 변경이 필요한 디자인은 먼저 사용자에게 설명하고 승인을 받는다.
- 콘셉트 이미지만 보고 실제 충돌 배치를 추측하지 않는다.

## 6. 핀볼 시각적 구조

- 화면 오른쪽에 배치되는 세로형 독립 장치다.
- 오른쪽 하단에 전통적인 플런저와 공 대기 위치가 있다.
- 슈터 레인은 오른쪽 가장자리를 따라 위로 올라가 메인 필드로 연결된다.
- 네 골은 동일한 중요도로 명확히 구분한다.
- 중앙은 범퍼, 핀, 공 궤적이 읽히도록 장식 밀도를 낮춘다.
- 공이 이동할 길과 충돌 장치를 장식보다 우선한다.
- 보드는 준비 단계에만 표시되고 전투가 시작되면 오른쪽으로 완전히 슬라이드 아웃한다.
- 보드가 사라진 뒤에는 같은 숲 전투 배경이 오른쪽까지 드러난다.

## 7. WebGL 셰이더와 VFX 제한

프로젝트는 Unity 6, URP 2D Renderer, PC WebGL 대상이다.

권장:

- 제한적인 Bloom
- 소수의 발광 마스크
- 공의 짧은 Trail
- 충돌 시 재사용 가능한 Sprite 파티클
- 단순한 Additive 또는 Alpha Blend 효과
- 골과 범퍼의 짧은 펄스
- 전투 바닥의 가짜 금색 조명 풀

피해야 할 것:

- 많은 실시간 2D Light
- 유닛마다 개별 실시간 광원
- 다중 패스 전체 화면 효과
- 고해상도 화면 전체 블러
- PNG 자체에 넓게 구운 Bloom
- 지나치게 많은 반투명 파티클 오버드로우

전투 화면의 금색 유닛 조명은 구현 가능하다. WebGL에서는 유닛마다 Light2D를 붙이기보다 다음 조합을 우선한다.

1. 바닥에 고정된 금색 조명 풀 또는 그라디언트 Sprite
2. 필요할 때만 사용하는 유닛 림라이트·Tint 마스크
3. 제한적인 Bloom

## 8. 새 채팅의 작업 방식

- 한 번에 전체 아트 세트를 생성하지 않는다.
- 매 단계에서 리소스 하나 또는 밀접한 한 세트만 제작한다.
- 생성 전 기능 요구사항과 분리 단위를 먼저 확인한다.
- 생성 결과를 무조건 칭찬하거나 승인하지 않는다.
- 해상도, 화면비, 알파 채널, 여백, 픽셀 밀도, 기능 적합성을 검수한다.
- 시각적으로 좋아도 게임 기능에 맞지 않으면 명확히 반려한다.
- 사용자가 “다음으로 넘어가자”고 하면 승인되지 않은 이전 시안을 억지로 수정하지 않는다.
- 사용자가 요청하기 전에는 코드나 Unity 씬을 수정하지 않는다.

## 9. 현재 핀볼 시안 상태

기존에 생성된 정사각형 아케인 핀볼 보드 시안은 최종 리소스로 승인되지 않았다.

반려 이유:

- 실제 골인 지점이 정확히 4개가 아니다.
- 골과 원형 범퍼가 시각적으로 혼동된다.
- 공, 플리퍼, 충돌 핀 등 동적 부품이 보드에 합쳐져 있다.
- 실제 게임의 골 기능과 물리 배치를 충분히 반영하지 못했다.

해당 이미지는 황동·석재·보라·청록 재질 참고 자료로만 사용할 수 있다. 구조 참고 자료로 사용하지 않는다.

## 10. 다음 작업 시작 조건

새 채팅에서 가장 먼저 할 일은 이미지를 생성하는 것이 아니다.

1. 이 문서와 기존 두 지침서를 읽는다.
2. 현재 Unity 핀볼 화면 스크린샷에서 실제 장치와 네 골의 위치를 확인한다.
3. 골, 범퍼, 핀, 플리퍼, 발사 레인의 기능을 서로 구분해 요약한다.
4. 보드 본체와 별도 Sprite 목록을 제안한다.
5. 사용자의 확인을 받은 뒤 첫 핀볼 리소스를 생성한다.

현재 Unity 핀볼 화면이 제공되지 않았다면 임의로 네 골의 위치를 결정하지 말고 해당 스크린샷을 요청한다.

## 11. 새 채팅 첫 요청문

다음 문장을 두 기존 지침서 및 이 문서와 함께 전달한다.

> 첨부한 세 지침서를 모두 읽고, `새 채팅 추가 인계 지침서`를 충돌 시 최우선 규칙으로 사용해 주세요. 현재 목표는 기존 게임 기능에 맞는 핀볼 아트 리소스를 순서대로 제작하는 것입니다. 이미지를 바로 생성하지 말고, 먼저 현재 Unity 핀볼 화면에서 정확히 4개의 골, 범퍼, 핀, 발사 레인, 공과 동적 부품의 위치 및 기능을 분석해 주세요. 그다음 보드 본체에 남길 정적 요소와 별도 Sprite로 분리할 요소를 정리하고 제 확인을 받아 주세요. 기존에 생성된 정사각형 보드 시안은 색상과 재질 참고용일 뿐이며 구조는 채택하지 않습니다.
